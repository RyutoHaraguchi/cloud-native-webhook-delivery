# 0005. 配信ワーカーに Fargate を使う

## 状況

配信の処理時間の大半は、送信先の応答待ちです。ワーカーは Lambda でも実装できます。

## 決定

ECS Fargate で常駐プロセスとして動かし、キューの滞留数で 0〜5 台に増減させます。

## 理由

- 1 プロセスで多数の応答待ちを効率よく扱え、接続も再利用しやすい
- 送信先ごとの同時送信数をメモリで数えられる
- コンテナのまま他のクラウドへ移しやすい

## 結果

- 0 台から動き出す最初の配信は数分遅れる
- `SIGTERM` の処理、ネットワーク設定、スケーリング設定が必要になる
- 配信のロジックは `core` にあるので、実行環境を替える場合の変更は入口が中心になる
