# 0002. 再送回数を配信レコードで管理する

## 状況

`ApproximateReceiveCount` は受信回数であり、送信回数ではありません。ワーカーの異常終了でも増えるので、再送の間隔がずれます。また、SQS による DLQ への自動移動はワーカーから検知できず、配信の状態が更新されません。

## 決定

- `attemptCount` と `nextAttemptAt` を配信レコードに持ち、再送の判断に使う
- 待機の方法は [ADR 0007](0007-retry-wait-outside-in-flight.md) で定める
- 最終失敗時は、ワーカーが `failed` を記録し、DLQ へ送信してから元のメッセージを削除する
- SQS の自動移動は、処理できないメッセージの隔離用に残す（受信回数の上限 20 回）

## 結果

- 再送の間隔と配信の状態が正確になり、判断を `core` に置ける
- 送信回数の条件付き更新と、DLQ への送信の実装が必要になる
- 送信後の記録に失敗すると重複配信が起きる。受信側の `webhook-id` による判別で許容する
