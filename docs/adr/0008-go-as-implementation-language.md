# 0008. 実装言語に Go を使う

## 状況

配信ワーカーは多数の応答待ちを扱い、TLS と署名の CPU 処理も発生します。全コンポーネントでドメインロジックを共有するので、言語は 1 つに揃えます。候補は Node.js + TypeScript と Go です。

## 決定

全コンポーネントを Go で実装し、単一モジュールで管理します。実行ファイルは `cmd/`、ドメインロジックとアダプタは `internal/` に置きます。

## 理由

- goroutine で多数の応答待ちを扱え、CPU 処理も複数コアに分散できる
- メモリ使用量が少なく、小さな Fargate タスクに収まりやすい
- `net.Dialer` と `http.Transport` で、SSRF 検査を接続処理に組み込みやすい
- 単一バイナリなので、Lambda とコンテナの成果物が小さい

## 結果

- Lambda はマネージドランタイムではなく、`provided.al2023` を使う
- TypeScript と比べて型の表現力は低く、エラー処理の記述量は増える
- 単一モジュールなので、依存の境界はディレクトリと `depguard` で守る
