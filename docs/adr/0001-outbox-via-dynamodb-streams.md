# 0001. Outbox パターンと enqueuer での配信生成

## 状況

受付で DynamoDB と SQS の両方に書き込むと、片方だけ成功した場合にイベントを失います。また、購読先への振り分けを受付で行うと、応答が遅くなり、1 トランザクション 100 件の制限を受けます。

## 決定

- 受付はメッセージを DynamoDB にのみ保存する
- DynamoDB Streams で起動する enqueuer が、購読先を調べて配信を作り、SQS に投入する
- 配信のキーをメッセージ ID と送信先 ID にして、再実行しても重複しないようにする

## 結果

- 受付の処理が軽く、送信先の数に制約されない
- 受付直後に送信先を変更すると、新しい設定が適用される場合がある
- Streams の保持は 24 時間なので、enqueuer の遅延を監視する必要がある
